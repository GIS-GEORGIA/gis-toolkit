# GIS_BOX — ტექნიკური აღწერა

ეს დოკუმენტი აღწერს, **რა ტექნოლოგიით, რა პრინციპებით და რა მეთოდებითაა** აგებული GIS_BOX —
არქიტექტურიდან დაწყებული, თითოეული ხელსაწყოს ალგორითმით, პლატფორმებით, შეფუთვითა და ტესტირებით
დამთავრებული. დოკუმენტი აღწერს **კოდის რეალურ მდგომარეობას** (გადამოწმებულია წყაროსთან); ის, რაც
არ არის გაკეთებული ან აქვს შეზღუდვა, ცალკე, პირდაპირაა მითითებული (იხ. §15).

> GIS_BOX-ში მხოლოდ სივრცითი / GIS ხელსაწყოებია. საოფისე-დოკუმენტური ხელსაწყოები (დოკუმენტებში
> ძებნა, ფაილების შეგროვება) ცალკე პროექტში — `Toolbox` — გადავიდა.

## 1. მოკლედ და ტექნოლოგიური სტეკი

GIS_BOX — **ერთფანჯრიანი desktop აპლიკაცია** (Python + tkinter), რომელიც ერთად აგროვებს პატარა GIS
ხელსაწყოებს. ინტერფეისი ორენოვანია (ქართული / English), აქვს light/dark თემა, და მუშაობს
Windows-ზე, Linux-ზე (და, პრინციპულად, macOS-ზე).

| ფენა | ტექნოლოგია | სად გამოიყენება |
|---|---|---|
| ენა | **Python 3.11+** (CI: 3.11 და 3.12) | ყველგან |
| GUI | **tkinter / ttk** (Tk 8.6, თემა `clam`) | მთლიანი UI |
| ვექტორული I/O | **pyogrio** (GDAL-ის ზედა ფენა), **geopandas**, **fiona/rasterio** (ბანდლში) | კითხვა/წერა: shp, gpkg, gdb, dxf… |
| გეომეტრია | **shapely** | კვეთები, საზღვრები, დალაგება |
| CRS | **pyproj** | UTM ზონის ცნობა, რეპროექცია |
| ცხრილები | **pandas**, **openpyxl** | CSV/Excel კითხვა, დაფორმატებული `.xlsx` |
| სურათი | **Pillow (PIL)** | ცხრილის PNG/DIB, ხატულები |
| OCR / PDF | **rapidocr-onnxruntime** (ნაგულისხმევი), pytesseract, easyocr; **PyMuPDF**; **OpenCV** | კოორდ. ამომღები |
| PostGIS | **GDAL `ogr2ogr` / `ogrinfo`** (subprocess), PostgreSQL/PostGIS | GDB → PostGIS |
| ლოკალური ბაზა | **SQLite** (`sqlite3`, stdlib) | სინქრონის აუდიტი |
| Windows API | **ctypes** (`user32`, `kernel32`, `shcore`), **pywin32 COM** | ბუფერი, DPI, Excel-ის დახურვა |
| განრიგი | tkinter `after()`; Windows **Task Scheduler** (`schtasks`) | GDB → PostGIS |
| შეფუთვა | **PyInstaller** (onedir), **nfpm** (deb/rpm), **AppImage** | გავრცელება |
| ტესტები | **pytest**, **xvfb** (Linux GUI) | 85 ტესტი |
| CI/CD | **GitHub Actions** | compile + tests + release |

**ბაზისური პრინციპი:** სტანდარტული ბიბლიოთეკა სადაც შეიძლება; მძიმე პაკეტები — მხოლოდ იქ, სადაც
რეალურად სჭირდება, და **ზარმაცად (lazy)** იტვირთება.

### 2.2 საბაზისო კლასი `ToolFrame`

ყველა ხელსაწყო არის `tools.base.ToolFrame`-ის (`ttk.Frame`-ის) მემკვიდრე:

- `__init__(master, app)` ინახავს `self.app`-ს და იძახებს `build()`-ს — ხელსაწყო თავად იგებს თავის UI-ს;
- `save_state()` — UI-ის ხელახლა აწყობამდე (თემა/ენა შეიცვალა) ინახავს ველების მნიშვნელობებს;
- `tr(key, **fmt)` — თარგმანი მიმდინარე ენით (იხ. §3.4);
- `log(msg)` — ჩაწერა საერთო ლოგში.

ხელსაწყო არაფერს „იცნობს“ სხვა ხელსაწყოს შესახებ; ურთიერთობა მხოლოდ `self.app`-ის (მთავარი აპი)
API-ით ხდება (`get_tool_config`, `set_tool_config`, `tool_state`, `palette`, `lang`, `log`,
`show_tool_by_tid`).

### 2.3 Lazy ჩატვირთვა

`_build_tool_specs()` აბრუნებს სიას:
`{name_en, name_ka, key/tid, factory(master)}`. **ხელსაწყოს frame იქმნება მხოლოდ პირველ არჩევაზე**
(`show(idx)` → `_instantiate_tool`). `factory` იმპორტს აკეთებს ფუნქციის შიგნით:

```python
def _make_zoneint_tool(self, master):
    from tools.zone_intersect import ZoneIntersectTool
    return ZoneIntersectTool(master, self)
```

შედეგები: სწრაფი გაშვება; ერთი გატეხილი ხელსაწყო (მაგ. აკლია დამოკიდებულება) **არ აჩერებს**
დანარჩენს — `_instantiate_tool` იჭერს გამონაკლისს და ცვლის მეგობრულ **error frame**-ით
(სტეკტრეისი + „რა უნდა დაყენდეს“).

### 2.4 „UI + სუფთა core“ გაყოფა

ლოგიკა, რომელიც შეიძლება ტესტირდეს GUI-ს გარეშე, გატანილია `*_core.py` (ან მცირე მოდულებში):

| UI | სუფთა ლოგიკა |
|---|---|
| `parcel_search.py` | `search_core.py`, `fields.py`, `regions.py` |
| `rename_transliterate.py` | `translit.py` |
| `geom_collect.py` | `geom_collect_core.py` |
| `zone_intersect.py` | `zone_intersect_core.py` |
| `shp_coords.py` | `xlsx_format.py`, `table_image.py`, `clipboard_html.py` |
| `gdb2postgis.py` | `gdb2postgis_core/_state/_audit.py` |

ეს არის ტესტირებადობის მთავარი წყარო: core-ს არ სჭირდება tkinter (ზოგს — არც GIS პაკეტები).

### 2.5 ხელსაწყოებს შორის გადაცემა (handoff)

„დაცვის ზონის კვეთა“ → „Shp → კოორდინატები“:
`app.show_tool_by_tid("shp_coords")` გადართავს ხელსაწყოს და აბრუნებს frame-ს; შემდეგ
`frame.load_external(path)` აყენებს საქაღალდეს, სკანირებს და ირჩევს ახლადშექმნილ shp-ს. ეს არის
**ერთადერთი** ჯვარედინი ურთიერთობა და ის საჯარო მეთოდებით ხდება.

## 3. UI ფენა

### 3.1 ttk + `clam`, პალიტრა და სტილები

- საბაზისო თემა — `clam` (ერთადერთი ჩაშენებული, რომელიც ფერების სრულ კონტროლს იძლევა ყველა OS-ზე).
- `THEMES = {"light": {...}, "dark": {...}}` — სემანტიკური ფერები:
  `bg, panel, sidebar, header, fg, muted, field_bg, field_fg, log_bg, log_fg, select, accent, accent_fg,
  accent_hover, border`.
- `apply_theme()` ერთ ადგილას აყენებს **ყველა** ttk სტილს (`TFrame, TLabel, TButton, TEntry,
  TCombobox, TLabelframe, Treeview, Progressbar, Scrollbar…`) პალიტრიდან. შედეგად ხელსაწყოები არ
  შეიცავენ ფერებს — მხოლოდ მინიჭებულ სტილებს.
- დასახელებული სტილები: `Accent.TButton` (მთავარი მოქმედება — ლურჯი), `Card.TFrame`,
  `Sidebar.TFrame/TLabel`, `Header.TFrame/TLabel`, `Title.TLabel`, `Muted.TLabel` და სხვ.
- თემის/ენის შეცვლისას `rebuild_ui()` ჯერ იძახებს მიმდინარე ხელსაწყოს `save_state()`-ს, შემდეგ
  ანადგურებს და თავიდან აგებს ინტერფეისს — ველების მნიშვნელობები ინახება `app.tool_state`-ში.

### 3.2 განლაგება

Header (სათაური + tagline + ენა/თემა მარჯვნივ) → hairline გამყოფი → **sidebar** (ხელსაწყოების
სია) | კონტენტი | ქვემოთ საერთო **ლოგი** (`tk.Text`, „გასუფთავება“ და „შენახვა .txt“).

### 3.3 Sidebar: drag-and-drop დალაგება

Sidebar არის `tk.Listbox` (ღილაკების ნაცვლად). მოვლენები `<Button-1>`, `<B1-Motion>`,
`<ButtonRelease-1>`:

- **დაჭერა** — იმახსოვრებს საწყის ინდექსს;
- **გადათრევა** — `nearest(y)`-ით განსაზღვრავს სამიზნე ინდექსს და `_move_tool(a, b)` **სინქრონულად**
  გადააადგილებს `tool_specs`-ს, `frames`-ს და Listbox-ის სტრიქონს;
- **გაშვება** — თუ იყო გადათრევა, `save_settings()` ინახავს რიგს; მერე `show(idx)` ხსნის ხელსაწყოს.

რიგი ინახება `tool_order` (სტაბილური `key`-ების სია) პარამეტრებში და ერთვება `_build_tool_specs()`-ში:
ახალი ხელსაწყო ბოლოში ემატება, წაშლილი იგნორირდება. Listbox-ის სიგანე **ყველაზე გრძელ სახელზეა**
მორგებული, რომ ქართული სახელები არ იჭრებოდეს.

### 3.4 ორენოვნება (i18n)

- თითო ხელსაწყო ინახავს თავის `CATALOG`-ს: `{key: {"en": "...", "ka": "..."}}` (scoped — გასაღებები
  არ ეჯახება).
- `tools/i18n.py::translate(catalog, key, lang, common=COMMON, **fmt)` — ერთი lookup ყველასთვის:
  **ხელსაწყოს catalog → COMMON → key**, ენა: **მიმდინარე → en → key**; `fmt` არსებობისას
  `.format(**fmt)`.
- `COMMON` — ხშირი გასაღებები (`browse`, `err`, `done`) ნებისმიერი ხელსაწყოსთვის fallback-ად.
- გამოტოვებული თარგმანი **არასდროს ვარდება** — ბრუნდება ინგლისური ან თვით გასაღები.
- ტესტი (`test_i18n.py`) ამოწმებს fallback-ის ჯაჭვს.

### 3.5 Tooltip-ები

`tools/tooltip.py` — დამოკიდებულების გარეშე `Toplevel`, რომელიც ჩნდება 500 ms hover-ის შემდეგ
(`<Enter>/<Leave>/<ButtonPress>`, `after`/`after_cancel`). `add_tip(widget, text)` აბრუნებს widget-ს,
ამიტომ პირდაპირ ჩაიწყობა: `add_tip(ttk.Button(...), "…").pack()`.

### 3.6 ფანჯრის მდგომარეობა

დახურვისას (`WM_DELETE_WINDOW` → `_on_close`) ინახება: ზომა/პოზიცია (`geometry`), ბოლო ხელსაწყო
(`current_tool`), `lang`, `theme`, `tool_order`. გაშვებისას ერთვება; საწყისი ზომა `1180x760`.

## 4. პარალელიზმი და პასუხიანობა

tkinter ერთნაკადიანია — **ხანგრძლივი სამუშაო UI ნაკადში აჭედებს მთელ აპს.** ამიტომ ყველა მძიმე
ოპერაცია მიჰყვება ერთ ნიმუშს:

```text
[UI thread]                          [worker thread]
 ღილაკი → threading.Thread(daemon) ──▶ სამუშაო …
 after(100, _poll_queue)  ◀── queue.Queue ── put(("progress"|"log"|"done"|…, payload))
 widget-ების განახლება მხოლოდ აქ
```

- **Tk widget-ს ვეხებით მხოლოდ UI ნაკადიდან.** worker-ი შედეგს `queue.Queue`-ში აგდებს;
  `_poll_queue` ყოველ 100 ms-ში კითხულობს (`get_nowait`) და ანახლებს UI-ს. `winfo_exists()`-ის
  შემოწმება იცავს გაუქმებული frame-ისგან.
- **გაუქმება:** `threading.Event`; worker პერიოდულად ამოწმებს `is_set()`-ს (ნაკვეთის ძებნა —
  თითო ბლოკს შორის, შეგროვება — თითო ფაილს შორის).
- **„თაობის მრიცხველი“ (`_meta_gen`)** ნაკვეთის ძებნაში: ბაზის/შრის სწრაფი გადართვისას ძველი
  (ჩამორჩენილი) წაკითხვა ახალს ვერ გადააწერს — შედეგს თან ახლავს თაობის ნომერი და შეუსაბამო
  იგნორირდება.
- **Lazy იმპორტი პასუხიანობისთვის.** გაზომილი: `pandas` ≈1.5 წმ, `pyogrio` ≈0.6 წმ. თუ მოდულის
  დონეზე იმპორტდება, ტაბზე პირველი დაწკაპება ≈2 წმ ყინავდა. ახლა ისინი იტვირთება საჭიროებისას,
  სასურველად worker ნაკადში (`_ensure_pyogrio()`); tool-ის იმპორტი ≈0.1 წმ. ტესტში
  `monkeypatch.setattr(search_core, "pyogrio", Fake())` მუშაობს, რადგან გლობალი უბრალოდ `None`-ია,
  სანამ არ დასჭირდება.
- ღილაკების მდგომარეობა (`disabled` სამუშაოს დროს) იცავს ორმაგი გაშვებისგან.

## 6. ხელსაწყოები — ალგორითმები

### 6.1 შაბლონის კოპირება (`TemplateCopier`)

- `TEMPLATE_SETS` — დეკლარაციული სია: `{id, name_en, name_ka, templates: {"37": base37, "38": base38}}`
  (და `zoned: False` ერთფაილიანი ნაკრებისთვის, მაგ. UTM ბადე). **ახალი ნაკრები = ერთი ჩანაწერი**,
  თითო ნაკრებისთვის ავტომატურად იქმნება sidebar-ის ჩანაწერი.
- კოპირება: `_files_for(zone)` პოულობს ყველა ფაილს, რომლის სახელიც იწყება ბაზით
  (`.shp/.shx/.dbf/.prj/.cpg/.sbn/.shp.xml…`); `_next_index(dest, base)` სკანირებს დანიშნულებას
  regex-ით `^{base}_(\d+)` და აბრუნებს `max+1`; ყველა თანმხლები კოპირდება ახალი ბაზით
  `shutil.copy2`-ით (თარიღები ინახება). შედეგი: `…_1, …_2, …` — არასდროს გადაწერს.

### 6.2 ნაკვეთის ძებნა (`parcel_search` + `search_core`)

1. **ნორმალიზაცია** (`normalize`): კოდიდან regex-ით `\d+` ჯგუფები → `NN.NN.NN.NNN`. უგამყოფო
   9-ციფრიანი (`2.2.2.3`) და 12-ციფრიანი (`2.2.2.3.3`) იყოფა ჯგუფებად; წამყვანი ნულები რჩება. ასე
   `71 63 80 094`, `71.63 .80 094`, `71,63,80,094` ერთსა და იმავე კანონიკურ ფორმაში მოდის.
2. **შეყვანა:** ხელით (ხაზი/მძიმე/`;`/ტაბი) ან CSV/Excel (`pandas`, სვეტის არჩევით); დუბლები იშლება
   თანმიმდევრობის შენარჩუნებით.
3. **ძებნა ბლოკებად:** `CHUNK_SIZE = 1000` კოდი თითო მოთხოვნაზე:
   `pyogrio.read_dataframe(gdb, layer=…, where='"CADCODE" IN (\'…\',…)')` — ფილტრი GDAL-ის დონეზე,
   არა მეხსიერებაში. აპოსტროფები ეკრანდება (`'` → `''`).
4. **შედეგი:** ბლოკების `GeoDataFrame`-ები `pd.concat`-ით ერთდება; იწერება **GeoPackage** და/ან
   **Shapefile** (`to_file`, utf-8); ვერნაპოვნი კოდები ცალკე სიად + `_NOT_FOUND.txt` shp-ის გვერდით.
5. **კოდის ველის ავტო-არჩევა** (`fields.pick_code_field`): `CADCODE_ID` (რიცხვითი) → `CADCODE` (სტრიქონი).
6. **შრეების სახელები:** `regions.REGION_CODES` — CadData-ის რეგიონების კოდები ქართულ სახელებზე
   (`R02 — ქვემო ქართლი`); `layer_display/layer_code` ორმხრივი გარდაქმნა.
7. **დაცვა:** თუ ბაზად მითითებულია `.gdb`-ების შემცველი **საქაღალდე** (და არა თვით `.gdb`), ხელსაწყო
   წინასწარ ამოიცნობს და გასაგებ მინიშნებას აჩვენებს (`_gdb_children`) — სხვაგვარად GDAL იძლეოდა
   ბუნდოვან „Permission denied“-ს.
8. მეტამონაცემების წაკითხვა (შრეები/ველები) ფონურია (§4); `pyogrio.list_layers` / `read_info`.

### 6.3 კოორდინატების ამომღები (`coordextract`)

პაკეტი, რომელიც რუკის სურათიდან/PDF-იდან იღებს კოორდინატებს:

- **`capture.py`** — შემოტანა: PDF გვერდის რასტერიზაცია **PyMuPDF**-ით (სისტემური ბინარი არ სჭირდება)
  ან **ეკრანის არეს დაჭერა** (ნებისმიერ ფანჯარაზე ხატავ მართკუთხედს) — უნივერსალური ხიდი ღია
  PDF-ისკენ. Windows-ზე ჩართავს DPI-awareness-ს (`ctypes.windll.shcore`), რომ პიქსელები ზუსტად
  დაემთხვეს.
- **`ocr.py`** — **ჩამოსაცვლელი backend-ები**, ავტო-აღმოჩენით: (1) `rapidocr-onnxruntime` — pip-ით,
  ოფლაინ, ნაგულისხმევი; (2) `pytesseract` (Tesseract ბინარი); (3) `easyocr` (მძიმე, torch). თუ არცერთია —
  გასაგები შეცდომა „რა დააინსტალირო“.
- **`georef.py`** — **აფინური გეო-რეფერენსი:** მომხმარებელი აძლევს საკონტროლო წერტილებს
  (პიქსელი → ცნობილი X/Y რუკის ბადიდან). სისტემა
  `X = a·px + b·py + c`, `Y = d·px + e·py + f` ისხნება **უმცირესი კვადრატებით**; 3 არაკოლინეარული
  წერტილი — ზუსტი ამონახსნი, მეტი — LSQ + **RMSE** (სიზუსტის შესაფასებლად). შემდეგ ნებისმიერი პიქსელი
  (მაგ. პოლიგონის წვერო) გადადის რეალურ X/Y-ში; ითვლება ფართობიც.
- **`export.py`** — CSV / JSON / XLSX; XLSX იყენებს იმავე გაზიარებულ ფორმატირებას, რასაც
  „Shp → კოორდინატები“ (`xlsx_format`). `cli.py` — headless ვერსია (`python -m coordextract.cli`).
- `coord_tool.py` ამ პაკეტს ჩასვამს ToolFrame-ში.

### 6.4 სახელების გადარქმევა (`rename_transliterate` + `translit`)

- **ტრანსლიტერაცია** `GEO2LAT` ცხრილით (მაგ. `ყ→y`, `შ→sh`, `ჩ→ch`, `ძ→dz`, `ღ→gh`; არქაული ასოებიც).
  `transliterate(name)`: ქართული → ლათინური; ლათინური/ციფრი/წერტილი უცვლელი; **ნებისმიერი სხვა
  სიმბოლო → `_`**; ზედიზედ `_` ერთდება, წერტილის წინ და კიდეებში იჭრება.
- **გეგმა** (`_build_plan`): თითო ფაილზე `{dir, old, new, status}`, სადაც status = `ok | conflict | exists`.
  `conflict` — ორი ფაილი ერთსა და იმავე ახალ სახელს იძლევა; `exists` — სამიზნე უკვე დისკზეა.
  არაუსაფრთხო ჩანაწერები **გამოტოვდება** და გამოიყოფა.
- **პროცესი:** წინასწარი სია → დადასტურება → `os.rename` (ყოველთვის თავიდან სკანირება, რადგან
  ფაილები შეიძლება შეცვლილიყო). **Undo:** ბოლო პარტიის `(new→old)` წყვილების სტეკი; აღდგენისას
  ვამოწმებთ, რომ ახალი არსებობს და ძველი — არა (არაფერი გადაიწერება).
- **მასალის შემოწმება:** `feature_count` კითხულობს `.dbf` header-ის ბაიტებს 4..7 (little-endian
  `uint32` = ჩანაწერების რაოდენობა) — GIS პაკეტის გარეშე; თუ `.dbf` არაა, `.shp` header-ის სიგრძით
  (≤100 ბაიტი = ცარიელი).

### 6.5 Shp → კოორდინატები

- **წაკითხვა:** `geopandas.read_file`; თუ CRS ცნობილია — `to_crs(epsg=32600+zone)`; წერტილი —
  `Point` / `MultiPoint` (ან ცენტროიდი).
- **UTM ზონა:** `pyproj.CRS.from_user_input(crs).utm_zone` → `"37N"`/`"38N"`; თუ CRS ვერ ცნობა —
  ხელით 37/38; თუ `.prj` საერთოდ არაა — გაფრთხილება „კოორდინატები ჩაითვლება არჩეულ ზონად“.
- **ცხრილი:** `№ / X / Y` (+ არჩევითი „გადაკვეთის კუთხე“). ⚠️ **კუთხე არ ითვლება გეომეტრიით** — ეს
  მომხმარებლის მიერ შეყვანილი ერთი მნიშვნელობაა („ყველასთვის ერთი კუთხე“), რომელიც `37°` ფორმატით
  იწერება; ცალკე ღილაკი არსებულ Excel-ში `°`-ს უმატებს. X/Y — მთელი (`int`, დამრგვალებული) ან წილადი.
- **ქუდი (ტექსტური სათაური):** ჩამონათვალი = ჩაშენებული ნაგულისხმევები + მომხმარებლის
  `shp_coords_templates.txt` (Notepad-ით რედაქტირებადი). ფაილი იკითხება კოდირების ჯაჭვით
  (`utf-8-sig → utf-8 → cp1251 → cp1252`).
- **Batch:** საქაღალდის ყველა წერტილოვანი shp ერთბაშად, ზონა თითო ფაილიდან.
- გამოტანა: §8.

### 6.6 GDB → PostGIS

ძრავა აღებულია დამოუკიდებელი **MIT** პროექტიდან (`gdb2postgis`) და ჩაშენებულია native tkinter-ით.

- **`ogr2ogr` აღმოჩენა:** `PATH` → ცნობილი QGIS/OSGeo4W გზები (ახალი QGIS-ის უპირატესობით).
  `_child_env` ცალკე, „სუფთა“ გარემოს ქმნის: ხსნის მემკვიდრეობით `PROJ_LIB/PROJ_DATA/GDAL_DATA`-ს
  (PostgreSQL-ის ინსტალაცია ხშირად ტოვებს მცდარ მნიშვნელობებს → `proj.db` კონფლიქტი) და
  მიუთითებს მოცემულ ბინარის გვერდით არსებულ data-საქაღალდეებზე.
- **წყაროების/შრეების ამოცნობა:** `.gdb` (საქაღალდე) და `.mdb` (ფაილი); შრეები და ველები `ogrinfo`-თი.
- **ბრძანების აგება** (`build_command`) — ყველა რეჟიმი ერთი ფუნქციიდან:
  - რეჟიმები: `-overwrite`, `-append`, `-update -append`;
  - **ინკრემენტული upsert:** `-update -append -upsert -preserve_fid` (FID სტაბილურია გაშვებებს შორის);
  - `-nln` (ცხრილის სახელი + პრეფიქსი), `-where`, `-nlt PROMOTE_TO_MULTI`, `-skipfailures`, `-t_srs`;
  - `-lco GEOMETRY_NAME / FID / SCHEMA / SPATIAL_INDEX=GIST|NONE / LAUNDER`;
  - `--config PG_USE_COPY YES` (სწრაფი COPY, სრული ჩატვირთვისას).
- **ინკრემენტული სინქრონი:** ორი ველი — `key` (მაგ. `OBJECTID`) და `change` (მაგ.
  `last_edited_date`), ავტო-აღმოჩენით (`auto_detect_key/track`). ყოველი შრისთვის ინახება
  **watermark** (`gdb2postgis_state.json`, გასაღები `"<abs-source>::<layer>"`). პირველი გაშვება — სრული
  ჩატვირთვა + watermark; შემდეგ — მხოლოდ `change > watermark` რიგები upsert-ით. არჩევით —
  **წაშლილების დეტექცია** (`_reconcile_deletes`: სამიზნიდან იშლება ის key-ები, რომლებიც წყაროში
  აღარაა). ცხრილის სრული ჩანაცვლება ხდება **staging ცხრილით და ერთ ტრანზაქციაში** (`_swap_staging`).
- **განრიგი:** აპის შიგნით — tkinter `after()` (დამოკიდებულების გარეშე, overlap-ის გარეშე,
  „შემდეგი გაშვების“ ჩვენებით). **აპის დახურვის შემდეგაც** (მხოლოდ Windows): `schtasks /Create`
  რეგისტრირებს დავალებას, რომელიც უშვებს `gis_box.py --gdb2pg-run` (headless, `gdb2postgis_cli.py`),
  კონფიგს კითხულობს `gis_box_settings.json`-იდან და წერს `gdb2postgis_run.log`-ს.
- **აუდიტი (SQLite):** ყოველი შრის გაშვებაზე იწერება თარიღი, დაზარალებული ობიექტების რაოდენობა და
  (თუ key ცნობილია) კონკრეტული ID-ები (ზღვარი `ID_CAP = 50000`, რაოდენობა ყოველთვის ზუსტია).
  „ისტორია“ ტაბი ამ ბაზით ეძებს თარიღით, აჩვენებს ID-ებს და საშუალებას იძლევა ობიექტები
  **სამიზნე ბაზიდანაც წაიშალოს** (`delete_features`).

### 6.7 გეომეტრიების შეგროვება → GeoPackage

- **ფაილების პოვნა:** `iter_geometry_files(folder, exts, recursive)`. ფორმატების კატალოგი
  `VECTOR_FORMATS` (SHP, DXF, DWG, GPKG, GeoJSON, KML/KMZ, GML, GPX, MapInfo, FlatGeobuf,
  SQLite/SpatiaLite, GeoParquet, DGN, File/Personal GDB, OSM, S-57, CSV) + „სხვა“ ველი ნებისმიერი GDAL
  გაფართოებისთვის (`normalize_exts`). **დირექტორია-დატასეტები** (`.gdb`) საქაღალდედ ინახება და შიგნით
  აღარ ჩავდივართ. დროებითი (`~$…`) და ფარული ფაილები გამოტოვდება.
- **კითხვა:** `pyogrio.list_layers` → თითო შრე `read_dataframe` (ერთ ფაილში რამდენიმე შრე იკითხება).
- **კლასიფიკაცია** (`_bucketize`): რიგი რეალური `geom_type`-ით ხვდება ერთ-ერთ კალათაში
  `point | line | polygon`; ცარიელი/`None` გეომეტრია იგნორირდება; ერთეული გეომეტრია გარდაიქმნება
  **Multi-**ტიპად (`_to_multi`), რომ GPKG-ის შრე ერთგვაროვანი იყოს.
- **CRS:** ავტომატური (პირველი ნაპოვნი) ან არჩეული (UTM 37N/38N). ცნობილი, მაგრამ განსხვავებული CRS →
  `to_crs`; უცნობი (`None`) → ჩაითვლება სამიზნედ (`set_crs(allow_override=True)`).
- **ჩაწერა:** ერთი GPKG, ზუსტად 3 შრე `points / lines / polygons` (`mode="w"` პირველზე, შემდეგზე `"a"`);
  ცარიელი კალათა გამოტოვდება. თითო ობიექტს მიჰყვება წარმომავლობა: `src_file`, `src_layer`, `src_type`.
- DWG დამოკიდებულია GDAL-ის CAD დრაივერზე; წაუკითხავი ფაილი გამოტოვდება და ლოგში აისახება,
  გაშვებას არ აჩერებს.

### 6.8 დაცვის ზონის კვეთა / ხაზების გადაკვეთა

ეს არის `arcpy.analysis.Intersect(..., output_type="POINT")`-ის ანალოგი **shapely-ით** (arcpy
საჭირო არაა).

1. **გენერალიზაცია** (`_as_curve`): პოლიგონი → მისი **საზღვარი**; ხაზი → **თავად ხაზი**.
   `crossing_points(a, b) = _as_curve(a) ∩ _as_curve(b)`. ასე ერთი ლოგიკა ფარავს
   პოლიგონი×პოლიგონს (ნაკვეთი × დაცვის ზონა), ხაზი×ხაზს (გაზსადენი × კომუნიკაცია) და შერეულს.
   (თავდაპირველად `.boundary` ხაზზე მხოლოდ ბოლო წვეროებს იძლეოდა — ამიტომ ხაზები „არ იკვეთებოდა“.)
2. **0-განზომილებიანი ნაწილების ამოკრება** (`_iter_points`): `Point/MultiPoint` → კოორდინატები;
   კოლინეარული გადაფარვა (`LineString/MultiLineString`) → ბოლო წვეროები; `GeometryCollection` →
   რეკურსია; პოლიგონი → იგნორი. გატეხილი გეომეტრია `try/except`-ით იცავს გაშვებას.
3. **დუბლების მოცილება** — კოორდინატები 4 ნიშნამდე მრგვალდება (`ndigits=4`) და `set`-ით ერთიანდება.
4. **ნუმერაცია — დერეფნის გასწვრივ.** ნაკვეთის საზღვრის შემთხვევითი წვეროდან დათვლა არასტაბილურია
   (რიგი შეიძლება დაწყებულიყო შუიდან). ამიტომ (`_corridor_axis`) ზონების გაერთიანების
   **minimum_rotated_rectangle**-ის გრძელი გვერდი განსაზღვრავს დერეფნის ღერძს; მიმართულება
   ორიენტირდება „ზემოდან ქვევით“ (ვერტიკალურ/დახრილ დერეფანზე) ან „მარცხნიდან მარჯვნივ“
   (ჰორიზონტალურზე). წერტილები ილაგება ღერძზე პროექციით, ტოლობისას — მართობული ღერძით. ღერძის
   ვერ დადგენისას fallback: `(-Y, X)`.
5. **ზონის არჩევა:** ატრიბუტით (ველი + მნიშვნელობა) ან „ყველა“. ველის ავტო-არჩევა
   (`_auto_zone_field`): `FID/OBJECTID/OID/GID/ID/…` (ზუსტი) → substring → პირველი ველი. ატრიბუტ-გარეშე
   shp-ისთვის ემატება **FID ფსევდო-ველი** (`0..n-1`), ფილტრი — რიგის ინდექსით (`iloc`).
6. **გამომავალი სახელი:** `<base><UTM ზონა>_<N>` — მაგ. `Gas_Pipe_ProtZone_Crossing38_1`; UTM ზონა
   მოდის ნაკვეთის CRS-იდან (`epsg-32600`/`epsg-32700`), `N` — პირველი თავისუფალი (`_1, _2, …`).
   Shapefile იწერება **`.prj`-ით**, ამიტომ „Shp → კოორდინატები“ ზონას თავად ცნობს. ველები: `N`, `X`, `Y`.
7. **CRS:** ზონა/მეორე ხაზი გადაიყვანება ნაკვეთის (პირველი) CRS-ში (`to_crs`).
8. `LineIntersectTool` — `ZoneIntersectTool`-ის თხელი **ქვეკლასი**: იგივე პაიპლაინი, ხაზ-ორიენტირებული
   წარწერები (`LTR` = `ZTR` + გადაფარვები), საკუთარი `tid` და `DEFAULT_NAME`. კოდი არ დუბლირდება.

### 6.9 რუკის სერვისები

`map_services.txt` — ტექსტური ფაილი (სახელის ხაზი, შემდეგ URL-ის ხაზი); ახალი სერვისი = ფაილის
რედაქტირება, კოდის შეხების გარეშე. ღილაკი ბუფერში აკოპირებს URL-ს (ArcMap/QGIS-ში ჩასასმელად).
`config_read_path` ჯერ მომხმარებლის ასლს ეძებს, მერე ჩაშენებულ ნაგულისხმევს.

### 7.1 ტრანსლიტერაცია ორივე მიმართულებით

  (`t→ტ`, `T→თ`, `q→ქ`, `R→ღ`, `S→შ`, `C→ჩ`, `Z→ძ`, `W→ჭ`, `J→ჟ` …); უცნობი სიმბოლო უცვლელია.

### 7.2 კლავიატურის „????“ პრობლემა და გადაწყვეტა

Windows-ზე ქართული კლავიატურით ტექსტის შეყვანა tkinter-ის `Entry`-ში `?`-ებად იქცეოდა.
დიაგნოზი: პრობლემა **შეყვანის გზაშია** (Tk-ის Windows `WM_CHAR` მოვლენა, რომელიც პროცესის
ANSI კოდირების გარეთ მყოფ სიმბოლოს უკვე დამახინჯებულს გადმოსცემს), **არა შრიფტში და არა Tcl-ის
`encoding system`-ში**. `tk.call("encoding", "system", "utf-8")` აპში დარჩენილია, მაგრამ ეს პრობლემას
**არ წყვეტს** — ჩვენება (UI-ის ქართული ტექსტი) მუშაობს, ტყდება მხოლოდ აკრეფა.

გამოსავალი — კლავიატურის გზის **შემოვლა** ისე, რომ ქართული ასოები აკრეფისას საერთოდ არ გამოიყენება:
1. **ფაილზე დაფუძნებული რედაქტირება** — ქუდების შაბლონები `shp_coords_templates.txt`-ში, რომელსაც
   მომხმარებელი Notepad-ში ასწორებს (იქ ქართული ნორმალურად იწერება); ფაილი კოდირების ჯაჭვით
   იკითხება;
2. **ლათინურ→ქართულ კონვერტერი** დიალოგში: მომხმარებელი აკრეფს ლათინურად (ASCII სანდოდ გადის),
   Python `lat_to_geo`-თი აქცევს ქართულად, ცოცხალი გადახედვა Sylfaen/DejaVu შრიფტით;
3. ბაზაში დამახინჯებული (`?`-ის შემცველი) ძველი ჩანაწერები მიგრაციისას იშლება, ახალი ჩანაწერი,
   რომელიც `?`-ს შეიცავს, უარიყოფა.

## 8. Excel, გაცვლის ბუფერი, სურათი

### 8.1 დაფორმატებული `.xlsx` (`xlsx_format.py`, openpyxl)

გაზიარებულია „Shp → კოორდინატებსა“ და კოორდ. ამომღებს შორის:

- `write_title` — ტექსტური ქუდი: **3 რიგი × N სვეტი merge & center**, `wrap_text`, Sylfaen (მუქი),
  **all borders** (merge-ის შემდეგ დიაპაზონის იტერაციით — რომ გარე ჩარჩო შენარჩუნდეს);
  `fit_title_rows` — რიგის სიმაღლე ტექსტის სიგრძეზე მორგებული (merge-ს Excel თავად არ ასწორებს);
- `write_block` — სათაური + მონაცემები, **center + middle** გასწორება, all borders, სვეტების
  სიგანე; კუთხის სვეტს ეძლევა `number_format = '0"°"'` (მთელი რიცხვი + გრადუსი, წერტილის გარეშე);
- `clean_number` — OCR/შეყვანის „ნაგვისგან“ თავისუფალი რიცხვი (სფეისი/ასო იშლება, `,`→`.`);
- `save_workbook` — `PermissionError` → **`FileLockedError`**.

### 8.2 ღია Excel ფაილის დამუშავება

წინათ ღია ფაილზე ექსპორტი იძლეოდა შეცდომას „დახურე“. ახლა:
`FileLockedError` → კითხვა „ფაილი Excel-ში გახსნილია — დავხურო (შეუნახავი ცვლილებები დაიკარგება) და
გავაგრძელო?“ → დიახ: `close_open_workbook(path)` **Excel COM-ით** (`win32com`,
`GetActiveObject("Excel.Application")`) პოულობს და ხურავს **ზუსტად ამ workbook-ს**
(`Close(SaveChanges=False)`), მოკლე პაუზა, ხელახლა ჩაწერა. თუ pywin32/Excel არაა (ან Linux) —
ფუნქცია `False`-ს აბრუნებს და მომხმარებელი „დახურე ხელით“ შეტყობინებას ხედავს.

### 8.3 ცხრილის კოპირება ბუფერში (`clipboard_html.py`)

მიზანი — ცხრილი „ისე, როგორც Excel-ში“ ჩაისვას სხვა პროგრამაში, **ფონისა და ფერის გარეშე**.

- **CF_HTML** (Windows): `ctypes` + `RegisterClipboardFormatW("HTML Format")`. ფორმატი მოითხოვს
  `Version:0.9 / StartHTML / EndHTML / StartFragment / EndFragment` header-ს **ბაიტური** ოფსეტებით
  (`_build_cf_html`, ტესტი: `test_cf_html_offsets`). ერთდროულად იწერება `CF_UNICODETEXT` (TSV).
- HTML ცხრილი მარტივია: `border="1"`, `border-collapse`, შავი 1px ჩარჩო, ცენტრირება, ფერის გარეშე.
- **ArcGIS Pro layout** HTML/ტექსტს „ბრტყელავს“ (ერთ ხაზად აქცევს), ამიტომ იქ გამოიყენება
  **სურათი**: `copy_image` — PIL → BMP → 14-ბაიტიანი header-ის მოცილება → **CF_DIB** ბუფერში.
- Windows-ის გარეთ `copy_table` ეცემა tk-ის ტექსტურ clipboard-ზე.

### 8.4 ცხრილის სურათად რენდერი (`table_image.py`)

`render_table(title, headers, rows, scale=6, transparent=True, supersample=2)`:

- **ხარისხი:** რენდერი `scale × supersample` მასშტაბით და **LANCZOS-ით** ჩამოსწორება — გლუვი
  ტექსტი, რომელიც layout-ში გადიდებისასაც არ ხეშდება;
- **პროპორციები:** სვეტების სიგანე შიგთავსით; ქუდი wrap-ულია სვეტების ჯამურ სიგანეზე; თხელი
  ჩარჩო (`bw = round(s·0.55)`), კომპაქტური რიგები;
- **გამჭვირვალობა და flatten-უსაფრთხოება:** LANCZOS-ის შემდეგ გამჭვირვალე ფონის RGB **შავი**
  რჩებოდა `(0,0,0,0)` — იქ, სადაც პროგრამა ალფას უგულებელყოფს (ბუფერი/flatten), მთელი სურათი შავი
  ჩანდა. გადაწყვეტა: შიგთავსს ვაერთიანებთ **თეთრ RGB ფონზე** და ალფას ხელახლა ვუყენებთ →
  გამჭვირვალე უბნები `(255,255,255,0)`: PNG-ში გამჭვირვალეა, flatten-ისას — თეთრი;
- ArcGIS Pro-სთვის უმჯობესია PNG **ფაილის** ჩასმა (Insert → Picture): ის ინარჩუნებს პროპორციას და
  გამჭვირვალობას (ბუფერიდან ჩასმა ხანდახან იწელებოდა).
- შრიფტი: `pil_font_candidates()` (Windows: Sylfaen…; Linux: Noto Sans Georgian / DejaVu…).

## 9. გეოსივრცული მეთოდები

- **CRS:** ყველა შიდა გამოთვლა UTM-ში (EPSG:**32637** / **32638**, WGS84 / UTM 37N/38N);
  ზონის ნომერი ↔ EPSG: `32600 + zone` (N), `32700 + zone` (S).
- **ზონის ცნობა:** `pyproj.CRS.utm_zone`; fallback ხელით არჩევა; `.prj`-ის არარსებობა — ცხადი გაფრთხილება.
- **რეპროექცია:** `GeoDataFrame.to_crs`; გამომავალ shp-ს ყოველთვის ეწერება `.prj`.
- **გეომეტრიის ოპერაციები:** shapely — `boundary`, `intersection`, `unary_union`,
  `minimum_rotated_rectangle`, `is_empty`, `geom_type`. **Multi-ტიპებზე ნორმალიზაცია** (`MultiPoint/
  MultiLineString/MultiPolygon`) ერთგვაროვანი GPKG-ის შრეებისთვის.
- **ფილტრაცია GDAL-ის დონეზე:** `where=` (pyogrio) და `-where` (ogr2ogr) — მონაცემი არ იტვირთება
  მეხსიერებაში, სანამ საჭირო არაა.
- **Shapefile-ის სტრუქტურა:** თანმხლები ფაილების ჯგუფი (`.shp/.shx/.dbf/.prj/.cpg/.sbn/.sbx/.shp.xml`)
  ყველა ოპერაციაში (კოპირება, გადარქმევა) ერთ ერთეულად მუშავდება; `.dbf` header-ის უშუალო კითხვა
  ობიექტების დასათვლელად.

3. **UI ნაკადი არასდროს იბლოკება** — worker + queue + `after`-polling, გაუქმება Event-ით.
4. **Fail-soft** — გატეხილი ხელსაწყო error frame-ს აჩვენებს, დანარჩენი მუშაობს; წაუკითხავი ფაილი
   ლოგში აისახება და გაშვებას არ აჩერებს.
5. **ერთი წყარო თითო საკითხზე** — თარგმანი (`translate`), გზები (`apppaths`), პლატფორმა
   (`platform_utils`), Excel-ფორმატი (`xlsx_format`), თემა (`apply_theme`).
6. **დეკლარაციული გაფართოება** — ახალი შაბლონი = ერთი ჩანაწერი (`TEMPLATE_SETS`); ახალი ხელსაწყო =
   `ToolFrame` + `_build_tool_specs` ჩანაწერი; ახალი სერვისი = ტექსტის 2 ხაზი.
7. **ნაგულისხმევად უსაფრთხო** — დადასტურება, წინასწარი სია, undo, არაგადაწერა, ორიგინალის შენარჩუნება.
8. **მონაცემი დისკზე ცოცხლობს build-ის გარეთ** — რესურსი ≠ მომხმარებლის მონაცემი.
9. **პლატფორმა — დეტალი, არა ფორკი** — ერთი კოდი, განსხვავებები ერთ მოდულში.
10. **ორენოვნება პირველივე დღიდან** — ყველა სტრიქონი catalog-შია, fallback-ით.
11. **გაზომვა ვარაუდზე მაღლა** — გაყინვის მიზეზი (იმპორტი 2 წმ) გაიზომა; PyInstaller-ის ქცევა
    ექსპერიმენტით დადგინდა (markers); CI-ის შედეგი ლოგში გადამოწმდა.

## 15. ცნობილი შეზღუდვები

- **Linux ჯერ ავტომატურად დამოწმებულია CI-ში (xvfb)**; რეალურ Linux-კომპიუტერზე ხელით გამოცდა და
  `.deb/.AppImage` ბილდების შემოწმება ცალკე ნაბიჯია.
- **მხოლოდ Windows:** Excel-ის ავტო-დახურვა (COM), HTML/სურათი ბუფერში, Task Scheduler განრიგი.
- **DWG** დამოკიდებულია GDAL CAD დრაივერზე (QGIS/OSGeo4W-ს ჩვეულებრივ აქვს).
- **GDB → PostGIS:** პაროლი გადაეცემა `ogr2ogr`-ს **კავშირის სტრიქონში** (ბრძანების არგუმენტად) —
  ლოგებში იფარება, მაგრამ გაშვების დროს ლოკალურ პროცესების სიაში ხილვადია. (გარემოს ცვლადით გადაცემა
  — შესაძლო გაუმჯობესება.)
- **FID ფსევდო-ველი** მხოლოდ ≤1000 ობიექტიან შრეზე ემატება (ჩამონათვალის ზომის დასაცავად).
- **„გადაკვეთის კუთხე“** არ ითვლება გეომეტრიულად — შეიყვანება ხელით.
- **დერეფნის ღერძის ლოგიკა** ეფუძნება ზონის გაერთიანების მინიმალურ მართკუთხედს; ძლიერ მრუდე
  დერეფანზე „ზემოდან ქვევით“ ნუმერაცია შეიძლება არ ემთხვეოდეს ვიზუალურ თანმიმდევრობას.
- GUI-ს ავტომატური ტესტი ფარავს აგებას და ძირითად ნაკადებს, არა ყველა დიალოგს/ღილაკს.
