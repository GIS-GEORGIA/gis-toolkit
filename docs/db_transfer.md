# ბაზებს შორის მონაცემთა გადატანა — სრული დოკუმენტაცია

ხელსაწყო: **ბაზებს შორის მონაცემთა გადატანა / Database Data Transfer** (GIS_BOX, გვერდითა მენიუდან).
კოდი: `tools/pgdb_transfer.py` (ფანჯარა) და `tools/pgdb_transfer_core.py` (მთელი ლოგიკა, UI-ის გარეშე).

---

## 1. რისთვისაა

ერთი ESRI **Personal Geodatabase**-იდან (`.mdb`) მეორეში გადააქვს ჩანაწერები **ერთი წლის** (ან რამდენიმე წლის)
მიხედვით. გადაიტანება სამი ტიპის ფენა:

| წყარო → მიმღები | გეომეტრია |
|---|---|
| წერტილი → წერტილი | Point |
| ხაზი → ხაზი | Polyline |
| პოლიგონი → პოლიგონი | Polygon |

გადადის გეომეტრია (ზუსტი ბაიტები, როცა CRS ერთია) და **ყველა ატრიბუტი**. წყარო მხოლოდ იკითხება; მიმღებში
**არაფერი იშლება და არაფერი იცვლება** — ემატება მხოლოდ ახალი ჩანაწერები.

## 2. წესები, რომლითაც ხელსაწყო წყვეტს, გადაიტანოს თუ არა ჩანაწერი

### 2.1 წელი
ჩანაწერი ეკუთვნის წელს, თუ მისი თარიღის ველი (`TariRI` / `TariRi` — რეგისტრი არ მნიშვნელოვანია) არის
`წელი-01-01 00:00:00` … `წელი-12-31 23:59:59` შუალედში.

### 2.2 დუბლიკატის წესი (მთავარი)
ჩანაწერი **გამოტოვდება მხოლოდ მაშინ**, როცა მიმღების **იმავე ფენაში** უკვე არის ჩანაწერი
- **იმავე `werilis_no`-თი** (წერილის ნომერი; გარე სფეისები იგნორირდება) **და**
- **იმავე წლის თარიღით**.

| სიტუაცია | შედეგი |
|---|---|
| მიმღებში ამ ნომერი + ამავე წელი უკვე არის | **გამოტოვდება** (დუბლიკატი) |
| მიმღებში იგივე ნომერია, მაგრამ **სხვა წლით** | **ჩაიწერება** |
| მიმღებში ამ ნომერი საერთოდ არ არის | **ჩაიწერება** |
| წყაროს ჩანაწერს `werilis_no` არ აქვს | **არ ჩაიწერება** (დუბლიკატობა ვერ შემოწმდება) — ანგარიშშია |

მიმღების შედარება ხდება **გადატანამდე გადაღებულ სნეპშოტთან**, ამიტომ ამ გაშვებით ჩაწერილი ჩანაწერები ერთმანეთს
არ ამოაგდებს.

### 2.3 განმეორებადი ნომრები წყაროს შიგნით
თუ წყაროში ერთი და იგივე `werilis_no` ერთ წელს რამდენჯერმეა და მიმღებში ამ წლით არ არის, **ყველა** ჩაიწერება
(ეს არ არის დუბლიკატი მიმღებთან მიმართებით). დიალოგსა და ლოგში ეს ჩანს როგორც **„ორაზროვნება / შენიშვნა“** —
მხოლოდ ინფორმაციაა, წესს არ ცვლის.

### 2.4 თარიღის პრობლემები
* **თარიღი ცარიელია (NULL)** — არც ერთ წელს არ ეკუთვნის, ძირითად გადატანაში არ მონაწილეობს; ჩამოთვლილია ლოგში;
  არჩევით ინახება ცალკე ახალ ბაზაში (იხ. 4.4).
* **თარიღი არასწორია** (არა თარიღი ან წელი 1990–2100-ს გარეთ) — არ გადადის, ჩამოთვლილია.

### 2.5 ფენების შესაბამისობა
ფენები ემთხვევა **გეომეტრიის ტიპით**, არა სახელით. თუ ტიპზე ორი ფენაა და ვერ ირჩევს, ხელით ირჩევ.
ფენა **გამოტოვდება** (და ეწერება მიზეზი), თუ: გეომეტრიის ტიპი არ ემთხვევა; გეომეტრიას Z/M აქვს; CRS განსხვავდება და
სანდო გარდაქმნა არ არსებობს; სქემა შეუთავსებელია; `werilis_no` ან თარიღის ველი ვერ მოიძებნა.
წყაროს ველი, რომელიც მიმღებში არ არის, არ გადავა (გაფრთხილებაა); ტექსტი, რომელიც მიმღების ველზე გრძელია, —
ჩანაწერის შეცდომაა.

### 2.6 კოორდინატთა სისტემა
CRS ერთია → გეომეტრია გადაიწერება **ბაიტ-ბაიტ**. განსხვავებულია და გარდაქმნა ცნობილია → გეომეტრია გადაიყვანება
(გაფრთხილებით). უცნობია → ფენა დაბლოკილია.

## 3. ფანჯარა — ელემენტი-ელემენტი

### 3.1 „საწყისი ბაზა“ და „მიმღები ბაზა“
ორი ცალკე ჩარჩო, თითოს **Browse** ღილაკი აქვს (`.mdb` ფაილის არჩევა). ქვემოთ სახელი და ზომა ჩანს:
`საწყისი: baza.mdb (…)` / `მიმღები: …`. ერთი და იგივე ფაილის არჩევა არ შეიძლება.

### 3.2 „გადასატანი წელი“
ტექსტის ველი:

| ჩანაწერი | მნიშვნელობა |
|---|---|
| `2026` | ერთი წელი |
| `2024-2026` | დიაპაზონი |
| `2024, 2026` | სია |
| `ყველა` (ან `all`) | წყაროში არსებული ყველა წელი |

რამდენიმე წელი მუშავდება **ერთიმეორის მიყოლებით**: თითო წელი ცალკე ანალიზდება, ცალკე გიდასტურებს დიალოგს,
ცალკე იწერება და **ცალკე ლოგი** აქვს. შუალედური „დასრულდა“ ფანჯრები არ გამოდის; ბოლოს ერთი ჯამური ფანჯარაა.
თუ რომელიმე წელზე „არა“ დააჭირე, ან შეცდომა მოხდა, დარჩენილი წლები აღარ მუშავდება.

ამ ახალი ბაზების შექმნა ძირითად გადატანას არ ცვლის: თუ ისინი ჩავარდა, მიმღებში ჩაწერილი რჩება, ხოლო შეცდომა
ცალკე ჩანს შეჯამებასა და ლოგში.

### 3.4 „ფენები (შესაბამისობა გეომეტრიის ტიპით)“
ცხრილი: თითო ტიპზე საწყისი ფენა და მიმღები ფენა. სტატუსი: `✓ დადგინდა` / `⚠ დარწმუნებით ვერ დადგინდა — აირჩიე
ფენები` / `⚠ ამ ტიპის ფენა არ არის`. ორაზროვნებისას ჩამოსაშლელიდან ირჩევ.

### 3.6 ქვედა არეები
* **პროგრესი და სტატუსი** — პროგრესის ზოლი და ხაზი „ფენა: i/n“.
* **გადატანის შეჯამება** — ფენა-ფენა და ჯამური რიცხვები, ხანგრძლივობა, სარეზერვო ასლისა და ლოგის გზა.
* **გაფრთხილებები და შეცდომები** — ჩანაწერები, რომლებიც ვერ გადავიდა, ცარიელი/არასწორი თარიღები, ორაზროვნებები.

### 3.7 დადასტურების დიალოგი
გამოდის ანალიზის შემდეგ. შეიცავს: წელს, საწყისი/მიმღები ბაზის სახელებს, თითო ფენაზე
`ნაპოვნია / მიმღებში უკვე არის / ჩასაწერია / შეცდომა`, **შენიშვნებს** (განსხვავებული ველები, CRS გარდაქმნა,
განმეორებადი ნომრები, ცარიელი/არასწორი თარიღები), სარეზერვო ასლის ინფორმაციას, დამატებითი ბაზების გზებს და
კითხვას „ჩაიწეროს N ჩანაწერი მიმღებში ახლა?“. თუ ჩასაწერი არაფერია, ამას გეუბნება (და, თუ ჩართულია, გთავაზობს
მხოლოდ თარიღის გარეშე ჩანაწერების შენახვას).

### 4.1 ლოგის შინაარსი
ლოგი **არასდროს გადაიწერება** — ანალიზი, ჩაწერა და შეჯამება ერთ ფაილშია.
1. თავსართი: წელი, საწყისი, მიმღები, პერიოდი, ფენების შესაბამისობა, პარამეტრები.
2. თითო ფენაზე: ჩანაწერების რაოდენობა **წლების მიხედვით** წყაროში და მიმღებში, ნაპოვნი, დუბლიკატი, ჩასაწერი.
3. **ყოველი ჩანაწერის** გადაწყვეტილება (`[DETAIL]`): გამოტოვებული — რომელი მიმღების OBJECTID-ის გამო;
   ჩაწერილი — წყაროს OBJECTID → მიმღებში მიღებული ახალი OBJECTID; შეცდომა; ცარიელი/არასწორი თარიღი.
4. ჩაწერა: მიმღების მწკრივები/სივრცითი ინდექსი ჩაწერამდე და შემდეგ, ექსტენტის ცვლილება, ვერიფიკაცია.
5. **საბოლოო ცხრილი:** წერტილი/ხაზი/პოლიგონი — ნაპოვნი, დუბლიკატი, ჩასაწერი, ჩაიწერა, შეცდომა, თარიღი არ აქვს,
   არასწორი თარიღი; ჯამი; სტატუსი (`COMPLETED`, `declined by user…`, `FAILED / ROLLED BACK`, …); ხანგრძლივობა.

## 5. როგორ იწერება მიმღებში (უსაფრთხოება)

1. **მხოლოდ კითხვა** ანალიზისას — არც წყაროს და არც მიმღებს არ ეხება.
2. **სარეზერვო ასლი** (თუ ჩართულია); დისკზე ადგილის შემოწმებით.
3. მიმღები იხსნება **Exclusive** რეჟიმში — თუ სხვა პროგრამას (ArcGIS/Access) ღია აქვს, ხელსაწყო გეტყვის და
   არაფერს ჩაწერს.
4. **ერთი ტრანზაქცია ყველა ფენისთვის** (წერტილი+ხაზი+პოლიგონი ერთად — ან არაფერი).
5. თითო ჩანაწერზე: ჩაწერა + `OBJECTID`-ის მიღება + სივრცითი ინდექსის (`<ფენა>_SHAPE_Index`) ჩანაწერი;
   ბოლოს მიმღების ფენის **ექსტენტის** გაფართოება (`GDB_GeomColumns`) — ისე, როგორც ArcGIS აკეთებს.
6. ერთი ჩანაწერის შეზღუდვის დარღვევა (მაგ. აუცილებელი ველი ცარიელია) მხოლოდ ამ ჩანაწერს აგდებს — ის ანგარიშში
   გადადის, დანარჩენი გრძელდება.
7. **ვერიფიკაცია კომიტამდე:** მწკრივების და ინდექსის რაოდენობა = წინა + ჩაწერილი; ყოველი ჩაწერილის გეომეტრია
   ბაიტ-ბაიტ და `werilis_no` ემთხვევა წყაროს. შეუსაბამობა ან გაუქმება → **ROLLBACK**, მიმღები უცვლელია.
8. კომიტის შემდეგ — დამატებითი ბაზები (საერთო / ცალკე / თარიღის გარეშე), თითო ცალკე ვერიფიკაციით.

**იდემპოტენტურობა:** იგივე წლის ხელახლა გაშვება არაფერს ამატებს — უკვე ჩაწერილები დუბლიკატად ითვლება.
